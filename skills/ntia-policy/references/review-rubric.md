# Review rubric

Use this rubric in Review mode. It defines the issue types to screen for, the evidence each one needs, how to set confidence, who can act, and which candidate actions to recommend.

## Issue types

Screen every section against every issue type. A section can have more than one.

| Issue type | What to look for | Evidence needed |
|---|---|---|
| Expired or completed | A program, pilot, deadline, transition, or one-time event that has ended. Look for termination, sunset, closeout, and "until" clauses, and for application windows tied to a single funding notice. | The rule's termination or sunset condition, plus a verified outside fact that the condition has occurred. |
| Stale reference | A document, edition, form, URL, office, or organization name that has been replaced or no longer exists. Look for "current version," dated editions, and hard-coded web addresses. | The rule text, plus the newer document or the replacement name from an authoritative source. A URL that redirects is minor; a URL that fails is not. |
| Superseded authority | The statute or executive order the rule implements has been amended, repealed, or renumbered. Check the part's authority line and any statutory cross-references. | The authority citation, plus the current statute text or the amending public law. |
| Duplicative | The rule restates requirements found elsewhere: in a statute, in 2 CFR part 200, in another CFR part, or in the NTIA Manual. | Side-by-side citations showing the same requirement in both places. Note whether the texts match exactly or have drifted apart. |
| Conflicting | Two provisions impose requirements that can't both be met, or that use the same term differently. | Both citations, with the conflicting text quoted briefly. |
| Obsolete technology or practice | References to retired technologies, systems, filing methods, or procedures. | The rule text, plus a source showing the replacement technology or practice. |
| Unnecessary burden | A reporting, certification, or recordkeeping requirement that no longer serves its purpose, or that another requirement already covers. | The requirement, plus a reason it no longer serves its purpose. Set confidence to Low unless the reason is documented. |
| Non-regulatory content | Guidance, instructions, or application directions written into rule text, such as "Please describe." | The rule text. Note that moving guidance out of a rule usually needs a rulemaking. |
| Editorial error | Typos, broken cross-references, missing words, or incorrect numbering. | The rule text, with the error quoted. |

## Survival and dependency checks

Before you recommend removing anything, check these points:

- **Exact trigger wording.** Test a termination, sunset, or expiration condition against its exact words. "Fully expended" isn't met by funds that are "obligated," "awarded," or "distributed." If your evidence uses a different word than the rule, the condition isn't verified.
- **Survival clauses.** Rules that end a program often keep some obligations alive, such as audits, inspector general authority, final reports, or the return of unexpended funds. Name the surviving obligations and the sections that carry them.
- **Open awards and obligations.** Grant rules can govern awards that are still in their period of performance or closeout, even after new awards stop.
- **Internal dependencies.** Find every section in the part that cites the section under review.
- **External dependencies.** Search other CFR parts and the NTIA Manual for references to the section. The eCFR full-text search and the Federal Register search are the fastest routes.

If a provision fails a survival or dependency check, list it under "Provisions to retain" with the reason, or change the candidate action to Amend or Consolidate.

## Confidence

| Level | Use when |
|---|---|
| High | The rule text shows the issue, and you verified any outside fact the finding depends on. |
| Medium | The rule text shows the issue, but an outside fact is unverified or the evidence is indirect. |
| Low | The finding rests on a pattern, an inference, or an unverified claim. Low findings always go in the open verifications list. |

## Who can act

| Actor | Covers |
|---|---|
| NTIA rulemaking | NTIA rules in 47 CFR Chapter III (Parts 300-302). Changes go through notice-and-comment rulemaking unless counsel finds an exception applies. |
| NTIA, through the IRAC process | Content of the NTIA Manual. A Manual change also needs an update to the incorporation by reference in 47 CFR 300.1 before the new edition binds federal agencies. |
| FCC | FCC rules, including the Table of Frequency Allocations in 47 CFR 2.106. NTIA's route is a filing or a request to the Commission. |
| Congress | Requirements set by statute. Rule text that only restates a statute can't remove the underlying requirement. |
| Other agency | Requirements owned elsewhere, such as 2 CFR part 200 (OMB) or Department of Commerce financial assistance terms. |
| International | ITU Radio Regulations and other treaty obligations. |

## Candidate actions

| Action | Use when |
|---|---|
| Remove | The provision has no remaining purpose and passes the survival and dependency checks. |
| Amend | The provision is still needed, but parts of it are outdated, wrong, or conflicting. |
| Update reference | Only a citation, edition, name, or URL needs to change. |
| Consolidate | The requirement is duplicated, and one location should govern. Name the location that should govern, if the evidence supports it. |
| Retain | The provision looked like a candidate but must stay. List it under "Provisions to retain." |
| Needs more information | A key outside fact can't be verified. Name the fact and the source to check. |

Mark Counsel review "Yes" for every Remove, Amend, and Consolidate action, and for any finding that depends on how a statute is read.
