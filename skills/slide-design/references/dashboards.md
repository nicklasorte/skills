# Dashboards and trackers

Stephen Few defines a dashboard as a single-screen display of the most
important information needed to do a job, designed for monitoring at a
glance. Use this file when you build a status tracker, a metrics page, a
one-page status slide, or a recurring update.

## Principles

1. **Fit on one screen or one slide.** If it scrolls or needs a second page,
   cut it or split it by audience.
2. **Answer "compared to what?"** Every number needs context: a target, last
   period, a trend, or a threshold. A number alone can't tell anyone whether
   to act.
3. **Use gray, plus one alert color.** Show everything in grays and dark
   blue, and use purple only for items that need action. Few's
   redesigns use grays throughout with a single red marker for the problem.
   If everything is colored, nothing stands out.
4. **Put the most important item at top left.** People read dashboards in
   the same Z pattern as slides.
5. **Group related measures** and align them in a grid.
6. **Prefer compact charts:** bullet charts for actual versus target,
   sparklines for trends, and small bars for comparisons.
7. **Label scales.** Every chart needs readable values or a scale.

## Avoid

- **Gauges, speedometers, and dials.** They take a lot of space for one
  number and often lack a usable scale. Use a bullet chart.
- **Traffic-light circles.** Red, yellow, and green aren't NTIA colors, fail
  colorblind viewers, and hide how close something is to the line. Show
  status as a word ("On track," "At risk") and a number, with purple only
  for items at risk.
- **Decoration:** 3D, glow, gradients, and background images.
- **Everything at once.** Include only what the audience acts on.

## Layout pattern for a one-slide status update

| Area | Content |
|---|---|
| Top | Headline sentence: the one status that matters |
| Top row | Three to five key numbers, each with a comparison (target or last period) |
| Middle | One chart showing the trend or progress toward the goal |
| Bottom | Two or three items that need a decision, each one line |

## Recurring trackers

For a tracker that people return to, build it as a page that keeps its data
(such as a dashboard artifact or a spreadsheet), not as a static slide, so
updates don't require rebuilding it. Keep the layout identical between
updates so readers can find things.
